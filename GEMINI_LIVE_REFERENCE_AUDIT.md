## 1. EXECUTIVE ARCHITECTURE OVERVIEW

### 1.1 Core Flow Diagram
```
[User Mic] 
   │ (16kHz Mono PCM 16-bit)
   ▼
[AudioRecorder] (AudioRecorder.kt)
   │ onAudioChunk(ByteArray)
   ▼
[AssistantEngine] (AssistantEngine.kt)
   │ sendAudio(data)
   ▼
[ConnectionManager] (ConnectionManager.kt)
   │ sendAudio(data)
   ▼
[GeminiWebSocketClient] (GeminiWebSocketClient.kt)
   │ sendRealtimeAudio(data) -> Base64 JSON
   ▼
[WebSocket] wss://generativelanguage.googleapis.com/.../BidiGenerateContent
   │
   ├─► [Server Content / Audio Chunk (24kHz Mono PCM)] 
   │        │
   │        ▼
   │   [GeminiWebSocketClient] -> [StreamingResponseManager] -> [AudioPlayer] -> [AudioPlaybackManager] -> [AudioTrack]
   │
   ├─► [Tool Call / Function Call Request]
   │        │
   │        ▼
   │   [GeminiWebSocketClient] -> [ToolDispatcher] -> [ActionDispatcher] -> [ExecutionEngine]
   │        │
   │        ▼
   │   [ToolResponse] -> Base64/JSON back to Gemini WebSocket
   │
   └─► [Input / Output Transcription]
            │
            ▼
       [AssistantEngine UI / State Updates]
```

### 1.2 Architectural Invariants & Non-Negotiables
1. **Raw WebSocket Implementation:** Uses raw OkHttp `WebSocket` (`okhttp3.WebSocket`) over the Generative Language bidirectional RPC. No Google Generative AI Android SDK or official Live SDK is used.
2. **Audio Format Asymmetry:** Input stream MUST be **16,000 Hz, 1-channel (Mono), 16-bit linear PCM**. Output stream generated by the server is **24,000 Hz, 1-channel (Mono), 16-bit linear PCM**.
3. **No Direct Tool Execution in Live Layer:** `GeminiWebSocketClient` does not execute Android actions directly. It delegates to `ToolDispatcher`, which maps Gemini Live function calls into unified action strings dispatched to `ActionDispatcher`.
4. **Silence Keep-Alive Loop:** Silent PCM heartbeats (160 bytes of zeroed PCM) are sent every 25 seconds during active connection to keep the bidirectional session alive.

## 3. WEBSOCKET CONNECTION & TRANSPORT SPECIFICATION

### 3.1 Endpoint & Authentication
- **Exact URI:**
  `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?key={API_KEY}`
- **Source File:** `GeminiWebSocketClient.kt`, line 150-153.
- **Auth Method:** API Key passed strictly via the `?key=` query parameter. No HTTP Bearer or OAuth headers are added to the WebSocket handshake request.

### 3.2 OkHttpClient Configuration
- **Instantiated in:** `GeminiWebSocketClient.connect()`
```kotlin
val client = OkHttpClient.Builder()
    .readTimeout(0, TimeUnit.MILLISECONDS)
    .writeTimeout(0, TimeUnit.MILLISECONDS)
    .pingInterval(10, TimeUnit.SECONDS)
    .build()
```
- **Read/Write Timeout:** `0` (Infinite/Disabled) to maintain long-lived bidirectional streaming.
- **Ping Interval:** `10` seconds via OkHttp protocol-level WebSocket ping frames.

### 3.3 Connection Lifecycle & Handshake Flow
1. `connect()` creates `Request.Builder().url(url).build()`.
2. OkHttp calls `WebSocketListener.onOpen()`.
3. Client state transitions to `ConnectionState.CONNECTING`.
4. `sendInitialSetup(tools)` is IMMEDIATELY fired as the very first text frame.
5. Client starts the silence heartbeat loop (`startHeartbeatLoop()`).
6. Upon receipt of first server content / tool / response frame, state transitions to `ConnectionState.CONNECTED`.

## 4. PROTOCOL FRAMING & WIRE FORMAT

### 4.1 Setup Message (Initial Frame)
Sent immediately inside `onOpen()`:
```json
{
  "setup": {
    "model": "models/gemini-3.1-flash-live-preview",
    "generationConfig": {
      "responseModalities": ["AUDIO"],
      "speechConfig": {
        "voiceConfig": {
          "prebuiltVoiceConfig": {
            "voiceName": "Aoede"
          }
        }
      }
    },
    "inputAudioTranscription": {},
    "outputAudioTranscription": {},
    "systemInstruction": {
      "parts": [
        {
          "text": "<System instruction built by PromptBuilder>"
        }
      ]
    },
    "tools": [
      {
        "functionDeclarations": [ ... ]
      }
    ]
  }
}
```
*Note:* MAX configures `responseModalities` strictly as `["AUDIO"]`. Both `inputAudioTranscription` and `outputAudioTranscription` are empty JSON objects `{}` to enable dual server-side transcription.

### 4.2 Realtime Audio Input Frame
Sent continuously by `sendRealtimeAudio(pcmData: ByteArray)`:
```json
{
  "realtimeInput": {
    "audio": {
      "mimeType": "audio/pcm;rate=16000",
      "data": "<Base64 encoded 16kHz PCM bytes>"
    }
  }
}
```

### 4.3 Realtime Video/Image Frame
Sent by `sendVideoFrame(jpegBytes: ByteArray)`:
```json
{
  "realtimeInput": {
    "mediaChunks": [
      {
        "mimeType": "image/jpeg",
        "data": "<Base64 encoded JPEG bytes>"
      }
    ]
  }
}
```

### 4.4 Heartbeat / Keep-Alive Frame
Sent every 25 seconds via `startHeartbeatLoop()`:
```json
{
  "realtimeInput": {
    "audio": {
      "mimeType": "audio/pcm;rate=16000",
      "data": "AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"
    }
  }
}
```
*(160 bytes of binary 0x00, equivalent to 5ms of 16kHz silence)*.

### 4.5 Tool Response Frame
Sent by `sendToolResponse(callId: String, name: String, responseJson: JSONObject)`:
```json
{
  "toolResponse": {
    "functionResponses": [
      {
        "id": "call-12345",
        "name": "open_app",
        "response": {
          "output": {
            "success": true,
            "message": "Opened WhatsApp"
          }
        }
      }
    ]
  }
}
```

## 5. AUDIO SUBSYSTEM FORENSIC AUDIT

### 5.1 Audio Recording (Input Pipeline)
- **Source File:** `app/src/main/java/com/example/voice/audio/AudioRecorder.kt`
- **Audio Source:** `MediaRecorder.AudioSource.VOICE_COMMUNICATION` (enables hardware AEC/NS on Android).
- **Sample Rate:** `16000` Hz.
- **Channel Configuration:** `AudioFormat.CHANNEL_IN_MONO`.
- **Audio Encoding:** `AudioFormat.ENCODING_PCM_16BIT`.
- **Buffer Allocation:** `AudioRecord.getMinBufferSize(...) * 2`.
- **Worker Thread:** Dedicated thread `AudioRecorder-Thread` executing a while loop reading into `ShortArray` and serializing to little-endian bytes:
```kotlin
val byteBuffer = ByteArray(readResult * 2)
for (i in 0 until readResult) {
    byteBuffer[i * 2] = (shortBuffer[i].toInt() and 0xFF).toByte()
    byteBuffer[i * 2 + 1] = ((shortBuffer[i].toInt() shr 8) and 0xFF).toByte()
}
```
- **VAD Processing:** `AudioProcessor.isSpeechDetected()` is explicitly hardcoded to return `false`. Client VAD is disabled in favor of Gemini Live's server VAD.

### 5.2 Audio Playback (Output Pipeline)
- **Source Files:** `app/src/main/java/com/example/voice/audio/AudioPlayer.kt` and `app/src/main/java/com/example/utils/AudioUtils.kt` (`AudioPlaybackManager`).
- **Sample Rate:** `24000` Hz.
- **Channel Configuration:** `AudioFormat.CHANNEL_OUT_MONO`.
- **Audio Encoding:** `AudioFormat.ENCODING_PCM_16BIT`.
- **Playback Mode:** `AudioTrack.MODE_STREAM`.
- **Audio Attributes:** `USAGE_MEDIA`, `CONTENT_TYPE_SPEECH`.
- **Queue Mechanism:** `LinkedBlockingQueue<ByteArray>` consumed by `MAX-AudioPlaybackWorker` thread running at `Thread.MAX_PRIORITY`.
- **Write Mode:** `audioTrack.write(data, 0, data.size, AudioTrack.WRITE_BLOCKING)`.
- **Audio Focus:** Requests `AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` upon playback start; abandons focus on queue drain.

### 6.2 ConnectionManager Reconnection Logic
- **Source File:** `ConnectionManager.kt`
- **Initial Retry Delay:** `1,000 ms`
- **Backoff Multiplier:** `2.0` (Exponential)
- **Max Retry Delay:** `30,000 ms`
- **Generation Token Counter:** `connectionGeneration: AtomicInteger` ensures stale callbacks from disconnected sockets are ignored.
- **Network Callback Reconnect:** Listens to `ConnectivityManager.NetworkCallback.onAvailable()` to trigger immediate reconnect without waiting for exponential backoff timer.

## 7. TOOL DECLARATIONS & DISPATCH PIPELINE

### 7.1 Registration & Declaration
- **Declaration Registry:** `ToolRegistry.kt` and `MyApplication.kt` register 45+ tool declarations.
- **Conversion to Gemini Schema:** Tool definitions specify parameters with type (`STRING`, `NUMBER`, `BOOLEAN`, `OBJECT`), required fields, and descriptions.
- **Injected into Setup:** Converted to `SetupMessage.tools[0].functionDeclarations`.

### 7.2 Tool Invocation & Dispatch Loop
1. Server emits `ServerMessage` containing `toolCall.functionCalls[]`.
2. `GeminiWebSocketClient` parses `FunctionCall(id, name, args)`.
3. `ToolDispatcher.dispatch(callId, name, args)` is invoked.
4. `ToolDispatcher` maps the name via `functionToActionMap` (e.g., `"open_app"` -> `ActionDispatcher.EXECUTE_APP`).
5. Context injection: `ToolDispatcher` injects `last_input_transcription` into args to allow actions to reference user voice input.
6. Execution completes asynchronously; `ToolDispatcher` calls `client.sendToolResponse(callId, name, resultJson)`.

## 8. SECURITY & CREDENTIAL MANAGEMENT

### 8.1 Key Storage
- **Source File:** `SettingsManager.kt`
- **Primary Mechanism:** `EncryptedSharedPreferences` (`jarvis_secure_settings`) backed by Android Keystore using `MasterKeys.AES256_GCM_SPEC` with `AES256_SIV` keys and `AES256_GCM` values.

### 8.2 Security Vulnerability / Fallback Flaw
- **Location:** `SettingsManager.getSecurePreferences()`
- **Observed Behavior:** If `EncryptedSharedPreferences` fails to open (e.g., Keystore corruption or OEM Keystore bug), the code catches the `Exception`, clears the preferences file, and if recreation fails again, **falls back to unencrypted standard `SharedPreferences`**.
- **Risk Severity:** HIGH — API keys can end up stored in plaintext on disk if Keystore initialization faults occur.

## 9. KNOWN DEFECTS & BUGS IN REFERENCE PROJECT

1. **Model Lock Bug:**
   - **File:** `GeminiWebSocketClient.kt`, line 118 (`sanitizeModelName()`).
   - **Bug:** Method returns `"gemini-3.1-flash-live-preview"` unconditionally, discarding model configuration from `SettingsManager`.
2. **Disabled Barge-In:**
   - **File:** `StreamingResponseManager.kt`, line 62 (`handleUserSpeaking()`).
   - **Bug:** `handleUserSpeaking()` is a no-op comment. When user speaks while model is talking, audio playback is not interrupted locally.
3. **No GoAway / Resumption Token Support:**
   - **File:** `MessageModels.kt` & `GeminiWebSocketClient.kt`.
   - **Bug:** Does not parse server `GoAway` or store `resumptionToken`. If connection drops mid-session, conversation context on the Gemini server is lost.
4. **AudioFocus Listener No-Op:**
   - **File:** `AudioFocusManager.kt`, line 42.
   - **Bug:** `OnAudioFocusChangeListener` does not duck or pause audio playback when third-party apps gain audio focus.
